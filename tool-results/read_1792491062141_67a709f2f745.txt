   141→   170→   170→

   166→   195→   195→- Refined edge lighting where appropriate.
   167→   196→   196→- Subtle differences in surface brightness.
   168→   197→   197→- Better corner radii and proportional padding.
   169→   198→   198→- Cleaner relationships between cards and backgrounds.
   170→   199→   199→- More deliberate spacing between grouped elements.
   171→   200→   200→
   172→   201→   201→Choose treatments based on the existing component, its purpose, and the active feature's theme.
   173→   202→   202→

   175→   204→   204→
   176→   205→   205→Some components should remain visually quiet. Others may deserve a more expressive appearance.
   177→   206→   206→
   178→   207→   207→The overall interface should feel like a coherent premium product rather than a collection of independently decorated cards.

   202→   231→   231→Use stronger treatments for important actions and quieter treatments for supporting elements.
   203→   232→   232→
   204→   233→   233→The final result should feel premium because of its restraint, precision, consistency, and attention to detail—not because every component has multiple effects.

   574→   603→   603→## 10. Performance Is a Core Requirement
   575→   604→   604→
   576→   605→   605→The visual refinement must not make the application slower.
   577→   606→   606→
   578→   607→   607→The app runs through an existing web frontend and mobile WebView, and its service is hosted on Render. Avoid adding unnecessary client rendering work, network traffic, heavy assets, libraries, or backend requests.
   579→   608→   608→
   580→   609→   609→Understand which work happens on the user's device and which happens on the server.
   581→   610→   610→
   582→   611→   611→Purely visual CSS effects generally affect client-side rendering; they should not be moved onto the backend merely because the service is hosted on Render. Nevertheless, unnecessary requests, oversized payloads, repeated API calls, server-side rendering regressions, or inefficient backend operations can affect overall responsiveness.
   583→   612→   612→
   584→   613→   613→### 10.1 Performance audit
   585→   614→   614→
   586→   615→   615→Investigate:
   587→   616→   616→
   588→   617→   617→- Slow screen transitions.
   589→   618→   618→- Excessive component re-rendering.
   590→   619→   619→- Long JavaScript tasks.
   591→   620→   620→- Unnecessary event listeners.
   592→   621→   621→- Repeated API requests.
   593→   622→   622→- Duplicate network calls on navigation.
   594→   623→   623→- Layout shifts.
   595→   624→   624→- Excessive DOM complexity.
   596→   625→   625→- Expensive filters and backdrop blur.
   597→   626→   626→- Repeated animations.
   598→   627→   627→- Memory leaks.
   599→   628→   628→- Event handlers not cleaned up when components unmount.
   600→   629→   629→- Large image or font assets.
   601→   630→   630→- Unnecessary dependencies.
   602→   631→   631→- Excessive timers, polling, or retry loops.
   603→   632→   632→- Slow list rendering.
   604→   633→   633→- Lag during scrolling or swiping.
   605→   634→   634→- Slow keyboard and input interactions.
   606→   635→   635→- Resource loading problems.
   607→   636→   636→
   608→   637→   637→Only claim a performance issue is confirmed when it is supported by profiling, measurements, or reproducible behavior.
   609→   638→   638→
   610→   639→   639→### 10.2 Optimize visual effects carefully
   611→   640→   640→
   612→   641→   641→When introducing or refining transitions and gradients:
   613→   642→   642→
   614→   643→   643→- Prefer transform and opacity animations when they reproduce the desired effect.
   615→   644→   644→- Avoid animating properties that repeatedly trigger expensive layout calculations where possible.
   616→   645→   645→- Avoid perpetual animations that offer no meaningful user benefit.
   617→   646→   646→- Avoid adding multiple expensive blur layers to every card.
   618→   647→   647→- Limit unnecessary repaint areas.
   619→   648→   648→- Load fonts and assets efficiently.
   620→   649→   649→- Avoid adding large animation libraries for minor effects.
   621→   650→   650→- Respect reduced-motion preferences where supported.
   622→   651→   651→- Keep touch interactions responsive during animations.
   623→   652→   652→
   624→   653→   653→Do not sacrifice a signature premium effect without first exploring an efficient implementation.
   625→   654→   654→
   626→   655→   655→### 10.3 Verify performance
   627→   656→   656→
   628→   657→   657→Use the available browser, device, and profiling tools to compare behavior before and after the changes.
   629→   658→   658→
   630→   659→   659→Check for regressions in:
   631→   660→   660→
   632→   661→   661→- Initial loading.
   633→   662→   662→- Navigation.
   634→   663→   663→- Scroll smoothness.
   635→   664→   664→- Button response.
   636→   665→   665→- Chat switching.
   637→   666→   666→- Text input.
   638→   667→   667→- Rendering large responses.

   641→   670→   670→When supported, capture measurable before-and-after results. If the required profiling tools are unavailable, state that performance has not been conclusively measured.
